# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Static single-page portfolio for Yeeun Jeon, served via GitHub Pages (repo name `esthyj.github.io` → `https://esthyj.github.io`). No build step, no package manager, no framework. The site is opened directly by the browser.

To preview locally, just open `index.html` in a browser, or serve the directory (e.g. `python -m http.server`). There is no test suite, linter, or CI.

## Three-file separation (load-bearing)

The site is intentionally split into three files, and they must stay split:

- `index.html` — content only (Korean copy, section structure, image refs)
- `styles.css` — all visual styling, color tokens under `:root`
- `script.js` — interactions (scroll progress, IntersectionObserver reveals, stat counter, mobile nav toggle)

Do **not** consolidate any of these back into a single `index.html`. The user has explicitly asked for them to remain separated.

Inline `<!-- … -->` blocks in `index.html` are an editing guide aimed at the site owner (not Claude) — they explain which file to touch for which kind of change and how to add a new experience block. When restructuring sections, keep those guide comments in sync.

## Hover affordances (only clickable things react)

Standing rule from 2026-08-17: **an element that cannot be clicked must not respond to the mouse at all** — no color change, no `transform` (lift or `scale`), no border/background appearing. The user's phrasing was pointed: "클릭이 안되는데 쓸데없이 테두리를 만들지 말아줘." A hover reaction is an affordance promising a click, so faking one on inert content is the defect.

Seven such effects were removed that day, along with the now-pointless `transition` declarations that drove them: `.chip:hover` (color + border-color + background) and `.chip:hover .chip-icon` (the icon's `opacity` .85 → 1 is now static .85), `.about-img:hover img`, `.exp-img:hover img`, `.edu-img:hover img`, `.award-photo:hover img` (all four were `transform:scale(1.05–1.06)`), and the two card lifts `.pub-card:hover` / `.award-card:hover` (`translateY` + `border-color`). Resting borders and backgrounds were **kept** — they are the card/chip's normal appearance, and the rule is about *change on hover*, not about chrome existing.

Every `:hover` rule left in `styles.css` targets an `<a>` or a `<button>`, and that is the invariant to preserve. Currently: `.logo`, `.nav-links a`, `.toc li a`, `.exp-head` (+ its `.exp-logo` / `.exp-chevron` children), `.highlight a`, `.pub-link`, `a.value-link`, `.copy-btn`. Before adding a `:hover`, check what the selector actually matches in `index.html` — `.pub-card` and `.award-card` are `<div>`s whose only real link sits *inside* them, which is exactly how those two lifts got there. Same check applies to `cursor:pointer` (only on the three real buttons) and to the images: `.about-img`, `.exp-img`, `.edu-img`, and `.award-photo` are plain framed `<img>` wrappers, not links, so they stay inert.

`.reveal`'s scroll-entrance `translateY` is unaffected and stays — it is a one-shot load animation, not mouse feedback.

## /audit custom command

`.claude/commands/audit.md` defines a project-local slash command. It is **inspection-only**: investigate the directory, report findings with priority, and stop. Do not edit files, compress images, or take any action inside the `/audit` flow — even if the findings are obvious. Wait for the user to issue a follow-up instruction.
